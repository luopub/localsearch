- **功能点 ID**：`F1-05`
- **代码版本**：`15180ca` 干净（`git rev-parse --short HEAD`；跑这些命令时 `git status --porcelain` 无输出）
- **关联验收项**：**A7**（不产生计划外持久化落点；`doctor` 报告 `HF_HOME`/`data_dir`/`TORCH_HOME` 实际值）
- **落点**：`src/localsearch/cli/commands/doctor.py`、`tests/unit/test_doctor.py`（本文件是 P1 阶段唯一一份报告）

## 这份报告里的输出怎么来的

命令都很短，原样记下来即可复跑：

```bash
# ① 真实机器上一次完整的自检（本报告第 1.1 节）
COLUMNS=200 PYTHONIOENCODING=utf-8 uv run lsearch doctor

# ② 一份"有问题"的配置（第 1.2 节）：data_dir 与 roots 都指向不存在的 Z:
COLUMNS=200 PYTHONIOENCODING=utf-8 uv run lsearch --config "$TMP/nope.toml" doctor

# ③ 逐条单测（第 1.3 节）与全量（第 1.4 节）
uv run pytest tests/unit/test_doctor.py -q
uv run pytest -q

# ④ A7 后半句的现场取证（第 1.5 节）
ls -d /d/localsearch-data

# ⑤ 来源栏的独立对照（第 1.6 节）——不由本程序自证
powershell.exe -NoProfile -Command "Get-ChildItem Env:TORCH_HOME -ErrorAction SilentlyContinue; [Environment]::GetEnvironmentVariable('TORCH_HOME','User')"
```

退出码依次为 **0 / 1 / 0 / 0 / 非零（ls 找不到该目录）/ 0**。

> **两个采集参数要说明，否则输出看起来会与你自己终端里的不一样**：
> - `PYTHONIOENCODING=utf-8`：本机 stdout **经管道时是 gbk（cp936）**，不设它，中文表格进日志就成乱码。这是采集需要，不是程序行为——`doctor` 自己没有改过任何编码相关的设置。**这条同时是给下游用的提醒**：脚本里 `lsearch doctor | ...` 时得自己设这个变量，见「遗留」第 3 条。
> - `COLUMNS=200`：rich 在**非终端**（管道/重定向）下按 80 列排版，表会折行折到读不出来。给一个宽值只为让报告里的表格是一整行。真在终端里跑会自动用终端宽度。

# 2. 分析

## 2.1 修掉的第一件事：环境变量的来源栏在撒谎

`doctor` 第一版跑出来是"全绿"的，但其中一行是错的：

```text
TORCH_HOME = D:/localsearch-data/models/torch   ← 系统已设        # 错
```

系统里根本没有 `TORCH_HOME`。**根因是我们自己**：`cli/main.py` 的根回调在子命令之前调 `bootstrap_env()`，而它是 `setdefault` 语义，**真的往 `os.environ` 里写值**。`doctor` 再回头读 `os.environ` 判断"这个值是系统给的还是我们补的"，读到的就只剩"有值"——于是把自己几毫秒前的写当成了系统的写。

**修法**：在 `bootstrap_env()` **之前**拍一份 `os.environ` 快照，存进 `CliState.env_at_start`，来源判断一律按这份快照做（`cli/state.py`、`cli/main.py`）。`effective_env()` 本来就是"只读不写、报告生效值"的函数，它的 `environ` 参数就是给这个用的。

**为什么值得单独记一条**：这一行错得**没有任何症状**。程序不报错、退出码是 0、表格是绿的，唯一的异常是**来源栏里那句中文**——而它恰恰出现在最需要它的地方：兜底项。三个变量里只有 `HF_HOME` 是系统设的，另外两个都是我们补的，如果来源栏永远写"系统已设"，它就没有存在的意义了。

回归测试两条，分别盯**判定**和**接线**：

- `test_env_source_is_attributed_against_the_start_snapshot`：喂一份空环境，`TORCH_HOME` / `HF_HUB_OFFLINE` 必须报"兜底值"；同时反向断言——**系统真设了的时候仍要报"系统已设"**（否则修完就变成另一个极端，两边都绿等于没测）。
- `test_cli_passes_the_start_snapshot_to_the_checks`：上一条测的是 `check_env` 这个函数**本身**，抓不到"`main()` 忘了把快照递下去"这种回归。这条改从 CLI 走一遍，把 `render` 换掉以拿到真实的 `Check` 对象再断言。

## 2.2 修掉的第二件事：`data_dir` 被文件挡住时报 OK

配置成 `C:/x/file/data`（`file` 是个**文件**）时，doctor 会一路绿灯，直到首次索引才炸。原因是我第一版只用 `os.access(祖先, W_OK)` 判可写——而**普通文件当然是可写的**，于是"能写"这个判断给了一个与"能把目录建出来"无关的答案。

**修法**：先找路径上**挡路的文件**（`_blocking_file`），找到就 FAIL；另外 `data_dir` 本身是文件时报 FAIL；`_existing_ancestor` 改为只返回**目录**。回归测试 `test_data_dir_blocked_by_a_file_is_a_failure`。

> 这类"判据本身不成立、却永远返回 OK"的检查，比一个报错的 bug 危险得多：它让自检表变成装饰。同一条思路下还写了一条 `test_side_effect_audit_detects_a_write`——**落点审计必须真的在读目录**，只比两个空元组的话它永远是 OK。

## 2.3 三种状态与退出码的取值

| 状态 | 含义 | 影响退出码 |
|---|---|---|
| `OK` | 没问题 | 否 |
| `WARN` | 现在能用，但你知道一下（模型还没下、根目录不可达） | 否，仍退 0 |
| `FAIL` | 这样跑不了（解释器版本不对、依赖缺了、数据目录建不起来） | **是**，退 1 |

P1 阶段"模型权重"必然是 OK（P0 已经把 1.39 GiB 下载到系统 `HF_HOME`），但**下一台机器上它会是 WARN**，而那不该是一条命令失败的理由——P1 用不到模型。这条口径写在模块文件头，并由 `test_exit_code_is_zero_when_only_warnings` / `test_exit_code_is_one_when_a_check_fails` 两条钉住。

## 2.4 `--config` 只能在子命令**之前**

Click 的约定：全局选项挂在分组回调上，只认子命令**之前**的位置。

```text
$ lsearch doctor --config X
No such option: --config            # 退出码 2（用法错误）
$ lsearch --config X doctor         # 正确
```

这不是 bug，但报出来的错与"选项名写错了"长得一模一样。测试里把这个顺序封成了一个 `run(box, *args)` 辅助函数，免得每条测试各踩一次。**用户视角的代价是真实的**：`lsearch doctor --config …` 读起来更自然。要不要给 `doctor` 也单独挂一份 `--config`，等命令多起来再定（记进「遗留」第 2 条）。

## 2.5 `doctor` 与 `config` 都不写日志文件

`LOG_FILE_EXEMPT_COMMANDS = {"config", "doctor"}`。理由与 A7 是同一个：**只读命令不该为了回答"环境对不对"就在数据目录里建目录、写日志文件**——否则"检查过"这件事本身改变了被检查的对象，而下次检查看到的就是上次检查留下的东西。

代价写在明面上：这两条命令的输出**只能靠终端重定向**留档，不会自动进日志。

# 3. 遗留

1. **`_snapshot()` 只审计数据目录的一层**。抓得住"建了目录、写了文件"这类改动，抓不住"改了深层某个文件"。将来数据目录会有几十万个条目，`rglob` 一遍会让 doctor 本身变慢。**判断是够用**（A7 要防的是"doctor 创建了落点"，不是"doctor 改了已有文件"），但这是个有意收窄的口径，写在这里。
2. **`lsearch doctor --config x` 报的是 `No such option`**，见 2.4。要不要给每条命令各挂一份全局选项的副本，等命令面变大再定。
3. **管道下的编码**：stdout 经管道时是 gbk（cp936），中文表格进日志会乱码。本次靠 `PYTHONIOENCODING=utf-8` 采集。`doctor` **没有**去改 `sys.stdout` 的编码——那是全局副作用，与"只读命令不带副作用"冲突。下游脚本自己设，或将来看 `F8-03` 那条（`HF_HOME` 告警与日志轮转）要不要在启动时统一处理。
4. **模型那一项只看文件在不在**，不加载、不推理。真正"能不能用"由 P2/P5 的 `F5-01` 落实。这是刻意的：一条要读 14GB 权重的自检命令没人愿意跑。
5. **`drive_type()` 的判据在本机被证明不可靠**（§3 的 E10：E: 报 `DRIVE_FIXED` 却非本地盘）。`doctor` 只用它把"可移动/网络/光驱/RAM 盘"标成可疑，`DRIVE_FIXED` 一律当"说不好"——即**不拿它做任何肯定性结论**。方案留给 P2。
